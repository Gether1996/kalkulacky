### 2.2 Cieľová štruktúra — BACKEND

Navrhujem package `django_calculators/calculators/services/data/` s **per-štát, per-rok** dátovými súbormi + loaderom.

```
calculators/services/
├── data/
│   ├── __init__.py          # loader: get_rates(country, year) -> RateSet
│   ├── registry.py          # {('SK',2026): sk_2026, ('CZ',2026): cz_2026, ...}
│   ├── sk_2026.json         # SK sadzby/limity 2026
│   ├── cz_2026.json         # CZ sadzby/limity 2026
│   ├── pl_2026.json
│   ├── hu_2026.json
│   └── schema.py            # dataclass/TypedDict + validácia rozsahu
└── config_variables.py      # PONECHAŤ ako tenký shim: re-exportuje SK aktuálny rok
                             # (spätná kompatibilita existujúcich importov)
```

**Formát: JSON (alebo TOML)** — čisté dáta, ktoré vieš editovať raz ročne bez Python syntaxe. Loader načíta stringy a **skonvertuje na `Decimal`** (money-math konvencia repa ostáva zachovaná). Každý súbor má metadáta:

```jsonc

    "priemerna_mzda": "1524.00",           // ← jeden zdroj (dnes 2 rôzne čísla!)
    "sources": ["Finančná správa SR", "Sociálna poisťovňa", "zákon 595/2003"]
```

Loader API (návrh):

```python
from calculators.services.data import get_rates
rates = get_rates("SK", 2026)          # RateSet; default year = aktuálny
rates.salary.nczd_monthly              # Decimal('497.23')
rates.meta.valid_until                 # date(2026,12,31)
```

Service funkcie prijmú `year` parameter (default = aktuálny rok) a čítajú z `get_rates(country, year)`. `validate_config_year` sa nahradí **reálnym výberom datasetu** (fallback + jasná chyba, ak rok chýba).

**Výhody:** pridať rok 2027 = skopírovať `sk_2026.json` → `sk_2027.json`, upraviť čísla, zaregistrovať. Žiadna zmena logiky. História rokov ostáva (audit, spätné výpočty).

### 2.3 Cieľová štruktúra — FRONTEND

Rozšíriť existujúci dobrý vzor `country-params.ts` o sesterské dátové moduly (per-štát, s poľom `year`/`round`):

```
frontend/src/app/i18n/  (alebo nový app/data/)
├── country-params.ts     # ✅ existuje (VAT, mzdové presety, currency)
├── energy-params.ts      # NOVÉ: ceny energií/palív, solár, heat-pump, per-štát+rok
└── subsidy-params.ts     # NOVÉ: dotácie (Zelená domácnostiam, Obnov dom, NZÚ) — 1 zdroj
```

Do `energy-params.ts` / `subsidy-params.ts` presunúť inline konštanty z:
- `heat-pump-calculator.component.ts:24-51,123-135` (SK/CZ ceny, palivá, dotácie, `CO2`, `SUBSIDY_RATE`)
- `renovation-grant-calculator.component.ts:31-36` (Obnov dom / NZÚ stropy)
- `car-insurance-calculator.component.ts:60-70` (poistné faktory)

**Daňové čísla von z i18n stringov:** `salary.nczdHint`, `salary.disabilityHint` a pod. → nech pipe skladá reťazec z konštanty (`{{ nczd }}`), nie z prozy zapečenej v 5 jazykoch.

### 2.4 Jeden zdroj pravdy naprieč FE↔BE (odporúčané)

Duplicity FE↔BE (CO2, `SUBSIDY_RATE_OF_COST`, dotačné stropy, NČZD v i18n) sa najlepšie odstránia **expozíciou sadzieb z backendu**:

```
GET /api/calculators/config/?country=SK&year=2026
→ { meta:{...}, salary:{...}, vat:{...}, solar:{...} }
```

Frontend si ich načíta (prípadne cachne cez `APP_INITIALIZER`), takže **frontend-only kalkulačky prestanú hardkódovať** to, čo backend už vie. Ideál: presunúť aj heat-pump/renovation math na backend (majú blízko k solar service). Pragmatický medzikrok, ak nechceš endpoint: jeden **generovaný** zdieľaný súbor.

### 2.5 Kompletný súpis hodnôt — čo kam patrí

Detailné tabuľky s `file:line + literál + [R]/[Š]` sú v §3 (SK) a §4 (CZ/PL/HU). Zhrnutie „čo je každoročné a musí ísť do dátového súboru“:

- **SK:** všetky thresholdy dane, NČZD, max/min vymeriavacie základy, min. mzda, priemerná mzda, daňový bonus, SZČO min. základy + limity (`100000`, `20000`), max DVZ nemocenské, rodičovské sumy, dôchodková hodnota/priemerný dôchodok, solárne dotačné stropy, VAT.
- **CZ/PL/HU:** thresholdy (36× priemerná mzda), zľavy na poplatníka, min. základy, dotačné stropy NZÚ, ceny PV/batérie, dôchodkové redukčné hranice — **všetko [R]**, dnes bez akéhokoľvek verzovania.
- **Frontend-only:** ceny energií/palív, HP/renovácia/solár dotácie, poistné bázy.
- **Stabilné [Š] (ostávajú, ale patria do datasetu pre poriadok):** odvodové sadzby, VAT sadzby (menia sa zriedka), fyzikálne/geometrické konštanty (BMI, unit-converter) — tie **netreba** presúvať, sú vedecké.
